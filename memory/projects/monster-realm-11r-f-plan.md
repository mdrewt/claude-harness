## Design decisions
1. **Scope tension → option (ii):** `interpolateHistory(snapshots, renderTime, stepMs = 0)`; 0/non-positive disables re-anchoring (legacy byte-for-byte). Wire `renderResolver.ts:110` to pass `this.#stepMs` — 1-line diff, declared `touches-delta:` in PR body. If audit rejects: STOP, never fall back to store-side re-stamping (rejected on 4 grounds: ADR-0090 precedent; incorrect for D>stepMs — arrival frame falls below re-anchored edge into the un-re-anchored previous bracket; render policy leaking into net data model; tests the wrong core).
2. **EWMA gap gate (store.ts:441-447):** skip update when `interval > JITTER_IDLE_GAP_STEPS × stepMs`, K=3, `<=` updates / `>` skips (at exactly 600ms: updates). One-sided — interval≈0 burst STILL updates. `receivedAt: now` write stays UNCONDITIONAL (else estimator freezes for any character that ever idled — next interval measured from stale baseline is gated again, forever). Ring append unconditional. EWMA carried forward across gap, NOT reset (deferral D-C). K derivation: floor K>2 (a coalesced-tick spike presents as interval≈0 + interval≈2×stepMs — genuine jitter, must stay in); ceiling: one gated-in sample moves delay by 0.25·(K−1)·stepMs → K=3 caps at +0.5 steps/sample; K≥13 saturates the 2.5 clamp in one sample.
3. **Constants file-local** (interpConfig.ts/config.ts are OUT of touches): `export const JITTER_IDLE_GAP_STEPS = 3` in store.ts; `export const REANCHOR_SPAN_STEPS = 2` + mirror `JITTER_IDLE_GAP_STEPS = 3` in interpolation.ts. Each test file pins its own constant to the literal, comment naming the twin. Consolidation = deferral D-A.
4. **Bracket re-anchor (interpolateHistory):** after the bracket scan and AFTER the existing rawSpan≤0 guard (on RAW span): if `stepMs > 0 && rawSpan > 2×stepMs`, `lower = next.receivedAt − stepMs`; `renderTime <= lower` → HOLD at prev position (dead zone; character genuinely stood there); else lerp over [lower, next] (span == stepMs). Threshold strictly `>` 2×stepMs (exactly 2×stepMs = one dropped tick = legitimate two-step slide; threshold 1 would re-anchor ADR-0090's burst windows). Lower edge is next−stepMs NEVER prev+stepMs (slide must END at arrival; front-anchored mutant moves char at gap start then freezes). Outer HOLD/clamp untouched, evaluated first. Multi-bracket rings re-anchor per-bracket by construction.
5. **Continuity proof (for ADR):** D = clamp(stepMs + 2·jitter, 0.5·stepMs, 2.5·stepMs) ≥ stepMs always (base=stepMs makes MIN unreachable) ⇒ at resume arrival T1, renderTime = T1−D ≤ T1−stepMs = lower ⇒ window always entered from dead-zone side at a=0. Pop impossible by construction. Bracket seam continuous (a=1 of bracket N = a=0 of bracket N+1 = same tile).
6. **JitterEstimator → option (a):** mirror the gate into `update()` (executable spec must not disagree with shipped rule; ADR-0142 doc-drift class). Zero existing tests change.
7. **Anti-patterns:** no extrapolation (ADR-0013); no snapshot mutation (tooth 17 pins); no net→render import; no module-level mutable config; no magic numbers (WHAT/WHY at file density).

## Adjudications (binding for tester + specialist)
1. **Red-team A (evolving-D backward wobble, closed-form max 0.2 tile at i=40ms):** ACCEPTED as bounded residual, NOT a design change. Verified: the identical wobble class/bound exists TODAY in ordinary brackets (Δa = Δdelay/span; span=stepMs ordinary vs re-anchored window stepMs — same denominator). Dead-zone hold floors the regression at prev (max back-step = min(a_before, Δdelay/stepMs) ≤ 0.2 tile, worst case second-arrival interval 40ms). The plan's "pop impossible by construction" claim is CORRECTED to: "entry pop impossible under constant D; time-varying D produces the same bounded wobble as pre-existing ordinary brackets (ADR-0090 class), floored by the dead zone." ADR must state the closed form. NEW TEST (T-A): deterministic evolving-D repro — A@0=(0,0) idle, B@5000=(1,0) gated, frame at now=5039.9 (delay 200 → a≈0.1995), C@5040=(2,0) (interval 40 → ewma 20 → delay 240), frame at now=5040.1 → a≈0.0005; assert the exact positions AND that the back-step ≤ 0.2 + never below prev (dead-zone floor). Store-side ewma math is store.test.ts territory; the render walk is interpolation/renderResolver territory (tester picks placement, likely renderResolver.test.ts using real store+resolver, or split).
2. **Red-team B (sustained 3.5×stepMs cadence → hold-then-slide loop, EWMA frozen):** INTENDED behavior, not a regression. Rationale (ADR): uniform 700ms single-tile arrivals = the server genuinely steps that entity every 700ms (a network stall would burst-deliver, hitting intervals ≤ K×stepMs and updating the EWMA; SpacetimeDB delivers per-transaction, and a fast mover delayed >1 tile snaps via shouldSnap). A discrete 1-tile step rendering as one ≤stepMs slide then rest is EXACTLY EARS E1 generalized, and matches the own-player SlideClock motion language (slide stepMs, rest until next step). The pre-fix "smooth crawl" (1 tile per 700ms continuous drift) is the DEFECT class the spec names, not a virtue. Bonus: EWMA staying frozen keeps delay at base (no lag inflation) — re-anchor makes wide-bracket rendering independent of span, so no adaptation is needed. NEW TEST (T-B): sustained-cadence walk (arrivals every 700ms, 1 tile each, stepMs=200): assert each step renders as a ≤stepMs slide completing at/near arrival+D, holds between, ewma stays 0, delay stays 200. Pins the semantics deliberately.
