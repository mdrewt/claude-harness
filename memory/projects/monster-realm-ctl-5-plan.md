## Anti-patterns to avoid
- No source-text scans, no greps of keymaps, no checks of checks, no new evals.
- No string literal button letters/glyphs to DOM sinks; ids reach `t()` only as literals.
- No `menuKeyInput` survivor; no second keydown path for the menu (the router is the only driver).
- Never route an event's edges twice (KeyboardSource treats a second keydown as lost-keyup).
- Do not edit `overlayRegistry.ts`, `index.html`, `styles.css`, `contextStack.ts`, `overlayA11yWiring.test.ts`, `main.input.test.ts`, `main.a11yFocus.test.ts` (outside touches; must stay green unmodified).

## Risks / known deviations (to flag in the PR)
- Sub-lists (Social/Profile/Options) are levels INSIDE the one menu frame (breadcrumb `Menu › Social`), not separate frames on the context stack: `FrameId`/`OverlayId` are closed unions in files outside touches. ctl-8d/8h replace them with tabs.
- canOpen non-exclusivity is realised in main.ts's `overlayVerdict` binder, not in the tier table.
- Escape in a sub-list closes the whole menu (top legacy overlay through the Escape ladder), matching ctl-6b's Start.
- `a11yCopy.ts` comments cite `ui/menuModel.ts:<line>` for overlay names; they go stale (outside touches → follow-up flag).

## Adjudication after plan review (reviewer + red-team) — BINDING, supersedes the rows above where they conflict

A1. `MenuView.setCovered(b)` writes `overlay.style.visibility = b ? 'hidden' : ''` (NOT z-index): most children are in-flow, unpositioned shells that a fixed menu would paint over. `visible` (reads `display`) stays true while covered.
A2. Enter-repeat: main.ts remembers each `e.code` whose press nav consumed and `preventDefault`s its OS-repeat keydowns until that code's keyup (so a held Enter cannot activate the child's focused button, e.g. `#claim-signin-btn`).
A3. overlayA11y: re-opening an id that is currently covered (suspended, not the top) is a no-op apart from keeping it suspended — no trap, no live-region adopt, no timer, no reorder.
A4. overlayA11y suspend order: if `document.activeElement` is inside the lower root, blur it FIRST, then set `inert`, then `aria-hidden="true"`. Resume removes `inert`/`aria-hidden` BEFORE any `focus()`. `OpenRecord` becomes mutable (or is replaced) for `returnFocus`, `uninstall`, `releaseLive`.
A5. `mainMenuPick(state, key)` with a key not in the current level is a no-op (never falls through to the cursor's item). main.ts ignores a pick while the menu is covered.
A6. The frame-loop announcement "top" is the context stack's top upper frame when the stack has one, else `visibleIds(overlayProbes)[0]` (so Account/Privacy opened over the menu are announced).
A7. main.ts router effects are applied by ONE exhaustive `switch` (`effect satisfies never` default) — never an if/else chain ending in `jump()`. ONE `routeCtx()` helper builds `{worldActive, nav}` for keydown, keyup and the frame tick.
A8. `keyboard.keydown(e)` is memoized per event (computed on first use at the nav intercept or the bottom router site, at most once).
A9. `MenuView` construction is idempotent over shared markup: if `#menu-rows` already sits inside an `.mr-frame` under `#menu-overlay`, reuse that frame instead of building a second one.
A10. The canOpen non-exclusivity stays in main.ts `overlayVerdict` (filter `menuView` out of the visible list for any target other than `menuView`) AND `docs/DECISIONS.md` "Client UI: one overlay registry, keyboard first" is amended in place: overlays are exclusive except the main menu, which stays open beneath the screen it opens and never blocks one; the menu sentence becomes the nav-list menu. (`openPrivacy` would otherwise deny with `blockedBy: 'menuView'`.)
A11. `menuView.test.ts` rewrite: the tester lists, in a header comment, every retired test id with its reason and survivor (or "none: the old keydown/hover/glyph contract is deleted by CTL5.2"); MV-NO-INNERHTML's property is kept as a behaviour test (no markup parsing of a label containing `<b>`), not a source scan.

Tests must kill these cheats: repeat test presses at a NON-zero `now` and ticks at press+349/350/449/450 plus a stall (press+1000 → exactly one edge, next due press+1100); `CTL5-6-LOWER-INERT` uses THREE records (only non-top roots inert+aria-hidden); CTL5-7 reads activeElement at callback time with outside-root, disconnected-descendant and inside-root cases; after `resetRepeat` a still-held key stays silent for 1000 ms; `CTL5-6-MULTI-POP-FOCUS-ONCE` closes base-first (menu then child) and asserts exactly one `focus()` call, to the world fallback; router `pop` never fires for a Backspace whose target is a text field (no edge from KeyboardSource).
