Behavioural consequences (each covered by a gating test):
- Escape/M above a base pops to the base (menu + child both close); at the world base opens the menu; on an Ongoing battle base does nothing (B17 — no hide); on a terminal outcome (battleView frame over the world) continues (sets `dismissedBattleId` via the pure rule). Popping a dialogue frame dismisses the conversation.
- Backspace pops exactly one frame (claimView included; B4). Escape on claimView closes it.
- R / Slash / Shift+Slash toggle help; `e.key === '?'` is gone.
- Typing: Escape in `#rename-input` blurs and keeps the text (overlay stays); a second Escape closes; Escape on focused `#rename-submit` closes (B5); Enter in the field commits via `setProfileName`.
- Q at the world still opens the journal (ladder); PageDown reaches the top adapter as RB (legacyAdapter → unhandled; asserted via `screenButton` with a stub adapter and via `routedBindings`).

## Anti-patterns to avoid
- No source-text scans, keymap greps, checks of checks, new evals.
- Never route one event's edges twice (memoized `keyboard.keydown`).
- No second keydown listener; no `stopPropagation` except the typing-mode Escape.
- Do not edit `renameView.ts`, `tradeProposeView.ts`, `overlayRegistry.ts`, `bindings.ts`, `index.html`, e2e specs (outside touches).
- No catch-all `default` in `dispatch` / `openFrame` / `screenButton` switches.

## Risks / deviations (flag in PR)
- B5 fixed by moving main's keydown listener to the capture phase + ownership, not by deleting the views' `stopPropagation` (the views are outside touches; their now-redundant listeners stay until ctl-8e/8h).
- After "stop typing" focus is on `<body>` (the legacy rename/propose shells have no nav container to return to); ctl-8h's typing row replaces this.
- `textEntry` frames have no producer yet; the pure rules are tested, main's `closeFrame` treats them as focus-only.
- Start/Select at the world keep today's `worldHasFocus()` guard (as KeyM/`?` had).

## Adjudication after plan review (reviewer + red-team) — BINDING, supersedes the rows above where they conflict

A1. **Only Escape moves to the capture phase.** main.ts registers the SAME `handleKey` (syncStack → onKeyDown → finally syncStack) twice: a capture-phase window listener that acts only on `e.code === 'Escape'`, and the existing bubble-phase listener for every other code. So the views' own `stopPropagation` keeps shielding their fields and submit buttons from the letter ladder exactly as today (red-team #2: a focused `#rename-submit` + N must not toggle-close rename and wipe the draft), while Escape can no longer be trapped (B5). No `ownership()` early return is added before the ladder. Enter stays bubble-phase: inside rename/propose fields the view's own Enter listener commits through its callback → `dispatch`.
A2. **Typing-mode Escape** (`typingKey(target, e)` in router.ts): returns `'stopTyping'` only when `e.code === 'Escape'`, the event is NOT composing (`isComposing !== true && keyCode !== 229`), and the target is a TEXT field — `TEXTAREA`, contentEditable, or an `INPUT` whose `type` is a text-like type (text, search, email, password, tel, url, number, or missing/empty). `SELECT`, checkbox/radio/range/button inputs are not text fields: Escape on them is Start. On `stopTyping` main moves focus to the first enabled non-text focusable (button, select, checkbox, `[tabindex]:not([tabindex="-1"])`) inside the field's `[aria-modal="true"]` root, falling back to `blur()`; then `preventDefault` + `stopPropagation` (the view's own Escape→hide never runs; the text is kept). A composing Escape is left entirely to the browser (no blur, no prevent, no stop).
A3. **applyStack derives, syncStack owns.** `applyStack(prev, next)` runs only the CLOSE side: `stackDiff(prev, next).closed` (no `opened` — YAGNI) in TOP-FIRST order (matches the retired Escape ladder; keeps the privacy `onDismissed` → `renderClaim` flush safe while claim is still visible), then `syncStack()` re-mirrors the stack from visibility, so CLEAR_HELD and `resetRepeat` run on the real edges. A dismissed dialogue stays visible and re-mirrored until the server batch removes it. `openMenu` / `toggleHelp` arms call `openMenu()` / `openHelp()` directly (help keeps NO identity guard — pre-join help works as today; menu keeps `identity !== ''`). `contextStack.ts` gains `popTop`, `popToBase`, `stackDiff` (closed only, top-first, structural keys), `continuedBattleId`.
A4. **Command union naming/arms:** the dispatch union is `Command` in `ui/screens/types.ts`; main.ts imports contextStack's as `StackCommand`. Claim arms: `claimSignIn`, `claimJoin`, `claimDecline` (the decline-confirmed callback); privacy arms: `deleteAccount`, `cancelAccountDeletion`, `requestDataExport`. UI-only steps (decline-requested/cancelled, delete-requested, confirm-cancelled, export-download, onDismissed, onPrivacy) stay as they are. `dispatch` is NOT `async`: each arm returns the reducer path's own promise or `DONE`.
A5. **Intentional test changes (Escape now means Start)** are allowed in sibling tests of main.ts and router.ts (listed under `touches-delta:`): `main.menu.test.ts` `CTL5-2-MAIN-ESCAPE-RETURNS` and the "Profile > Account … Escape" case; `main.input.test.ts` `CTL2-3-BOOT-B17` and `CTL3-2-BOOT-OUTCOME-SAME-BATCH` (preconditions that Escape hides an Ongoing battle); `router.test.ts` `CTL5-2-ROUTER-B-POPS-COVERED` (same tag, now asserts the screen's pop command); `main.a11yFocus.test.ts` / `main.privacyWiring.test.ts` where they press Escape. Each retarget keeps its test name/tag and gets a one-line comment naming CTL6B.x as the reason. Any OTHER red after implementation goes back to the tester for adjudication.
A6. **Test oracles must be non-vacuous** (red-team #1, #4, #8, #9): dialogue — `#dialogue-overlay` still displayed after Escape and after Backspace, exactly one dismiss while pending (Escape ×2), hidden only after a no-conversation batch; Ongoing battle — precondition overlay visible + base battle, Escape leaves it visible, W predicts no step, and the SAME key on a terminal outcome hides it (control); outcome continue — Escape AND Backspace each continue, and a SECOND terminal battle with a new id still shows; help — Select works before join (`identity === ''`), Slash and Shift+Slash `defaultPrevented`; typing — rename input AND a trade-propose currency input: value kept, `activeElement` not the field and inside the overlay, overlay visible, second Escape closes; Escape on the propose `<select>` and on a checkbox closes directly; a composing Escape is not prevented; letters on a focused `#rename-submit` toggle nothing (regression pin for A1); CTL6B-1-MAIN-DISPATCH covers at least one same-shape pair (e.g. trade accept vs reject, or challenge accept vs decline) asserting the exact reducer and args.
