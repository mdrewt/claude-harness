## Design (fixed contract for the tester)
1. **`notify` job** appended to nightly.yml:
   `needs: [mutation, mutation-server, coverage, smoke-republish, changelog-freshness]`,
   job-level `if: failure()`, job-level `permissions: {contents: read, issues: write}`
   (least privilege — top-level stays `contents: read`; the mutation jobs compile
   third-party build scripts and must NOT hold issues:write). Grant + step land in the
   SAME diff (spec CRITICAL).
2. **Mechanism = `gh` CLI** with `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`, `set -euo pipefail`,
   no `|| true` / `set +e` / `continue-on-error` — a 403 must red the notify job.
   Failing jobs enumerated from `NEEDS_JSON: ${{ toJSON(needs) }}` via
   `jq -r 'to_entries[]|select(.value.result=="failure")|.key'` — never five hardcoded branches.
   All `${{ }}` values pass through `env:`, never interpolated into the shell body.
3. **One issue per failing job per RUN** (title `nightly: \`<job>\` failed (run <id>)`, body
   names the job + result + links `$RUN_URL`). **Cross-night dedupe DROPPED** after plan
   red-team/review (ADR-0200 D5): prefix-ambiguous marker match, >100-open-issues blind spot,
   and no in-scope way to give the branch a permanent test. No `--label` (a nonexistent label is
   a new silent-failure surface). The loop counts what it opened and `exit 1`s if it opened
   ZERO while `if: failure()` fired (ADR-0200 D6).
4. **Artifact**: one step in `mutation` and one in `mutation-server`,
   `uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4`,
   `if: always()`, distinct `name:` per job (v4 hard-errors on duplicates),
   `path: mutants.out/`, `if-no-files-found: warn` (an `error` would mask the real failure),
   `retention-days: 14`.
5. **`jobIsNotNeutered` carve-out** (inside the wiring eval only; String methods /
   literal regex only — no `new RegExp`, semgrep `detect-non-literal-regexp`):
   split the job block at `steps:`; job-level region: ANY `if:` or truthy
   `continue-on-error:` -> not-ok. Segment steps at lines with the step dash indent;
   suppress block scalars (`|`, `|-`, `>`, `>-`) so `run: |` bodies are data;
   HARDENING adopted from the plan red-team (all fail-closed):
   (a) use an in-file `strictJobBlock` that terminates only at a non-blank NON-comment line at
       indent <= 2 (a 2-space comment truncates the shared `extractJobBlock`, hiding a neuter);
       `extractJobBlock` itself stays untouched (10 callers, outside touches);
   (b) anchored key match tolerating `"if":` and `if :`;
   (c) `continue-on-error` becomes an ALLOWLIST of the literal `false` (the old truthy blacklist
       admitted `${{ github.event_name == 'schedule' }}` — false under dispatch, true on cron:
       a neuter calibrated to hide from the drill);
   (d) fail closed on flow-style steps (`- {`), flow `steps:` sequences, YAML aliases/merge keys,
       a missing `steps:` key line (anchored `trim() === 'steps:'`, never indexOf), a missing dash;
   classify a step as an upload step iff one of ITS OWN keys is `uses:` whose value
   (comment tail stripped, truncated at the last `@`) EQUALS `actions/upload-artifact`
   and the step has no `run:` key. Admit `if:` ONLY on an upload step AND only when the
   value is exactly `always()` / `${{ always() }}`. `continue-on-error` NOT loosened
   anywhere. No `steps:` / no step dash -> not-ok (fail closed).
6. **New predicates** (all called in the real-file section, job names spelled out per call):
   `mutationJobUploadsMutantsOutOnFailure(yaml, job)`, `nightlyNotifyCanOpenIssues(yaml)`,
   `noOtherJobHoldsIssuesWrite(yaml)` (least-privilege negative space),
   `nightlyNotifyIsWired(yaml)` (needs-set derived from the file's own job keys so a 6th
   job added without wiring REDs). `jobIsNotNeutered` is NOT called on `notify`
   (legitimate job-level `if: failure()`); its neuter axes are covered by the notify predicate.
