## Defect (measured)
- Cascade (accounts.rs:1083-1101): 6a `resolve_all_live_interactions` → 6b erase_* → `battle::anonymize_battles` → terminal stamp.
- `anonymize_battles` (battle.rs:1573-1598) `continue`s past `Ongoing` rows — pinned by polarity in `battle_tests.rs:6241` per ADR-0228 D2 / RT-11 ("keep the deadline so the survivor can win by timeout").
- `pvp::forfeit_on_disconnect` (pvp.rs:645-701) log-and-continues on an `apply_pvp_forfeit` Err. `settle_pvp_battle` is infallible TODAY → the arm is unreachable; the hole is latent and unguarded.
- TWO post-terminal channels under the skip (record both in the ADR): (a) `submit_pvp_action` is class-(i) rostered (not deletion-gated), so an erased identity can settle the surviving row and re-mint `player_wallet` (economy.rs:29-45 insert-if-absent) + `pending_evolution_notice`; (b) the kept deadline reaper itself: 6b deleted the erased side's `battle_action` rows, `pvp_deadline_forfeit_side(false,false)` = SideA (game-core pvp.rs:77-87), so an unpicked side-A SURVIVOR forfeits, the ERASED identity wins, and `apply_pvp_rating` → `get_or_init_profile(erased)` re-mints a profile row (ranking.rs:106-122). Retiring the skip is strictly better for the survivor.
- Test vehicle: the native host has NO update/insert/table-scan → `anonymize_battles` cannot execute natively; `ctx.database_identity()` is an unstubbed link symbol. Pure seam + in-crate source-scan pins (concat! needle hygiene mandatory).
