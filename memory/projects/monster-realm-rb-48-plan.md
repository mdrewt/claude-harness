## 1. Design decision

### D1 — Location is forced, not chosen
`export_bundle` writes are module-isolated to `privacy.rs` (G5/D0; `privacy.rs:1-3`, `accounts_tests.rs` `rb22_purge_naming_budget` at `:5272`). A new module file would trip the `mod` census (`accounts_tests.rs:3899-3931`) and `m22_scanned_sources` (`:3514`). The reaper **must** be in `/home/mdrewt/projects/ai-apps/claude-harness/projects/monster-realm/server-module/src/privacy.rs`.

### D2 — Global interval singleton, mirroring `playtest.rs:31-38, 156-202`
```
ExportBundleReaperSchedule { id: u64 #[primary_key] #[auto_inc], scheduled_at: ScheduleAt }
accessor = export_bundle_reaper_schedule, scheduled(export_bundle_reaper), PRIVATE
```
No `Identity` column ⇒ `NotOwned` in the manifest ⇒ **no `REKEY_MANIFEST` entry** (G6 keys on Identity columns only — verified: `evals/guest-claim-integrity.eval.mjs` scope is `ACCOUNTS_PATH` at `:473`) and **no `[DEL-*]` cascade obligation** (`m22s3b_cascade_covers_manifest` skips `NotOwned`, `accounts_tests.rs:9886-9894` — **no edit needed there**).

Rejected, with reasons: **per-request one-shot** (needs an Identity column → REKEY entry in an out-of-touches eval; an arm inside the statement-pinned `request_data_export` body; and structurally cannot reach pre-slice legacy chunks). **btree index on `created_at_ms` + range filter** (pushes the decision into the DB where no native test can observe it; the pure seam is the whole point of the proof).

### D3 — Functional core / imperative shell
**Pure (tested directly, the entire behavioural proof):**
```
fn plan_export_reap(rows_sorted_by_id_asc: &[(u64, i64)], now_ms: i64, ttl_ms: i64, batch: usize) -> Vec<u64>
```
`now_ms.saturating_sub(created) >= ttl_ms` ⇒ expired; result truncated to `batch`. This is `playtest::plan_reap` (`playtest.rs:62-89`) minus the cap-overflow arm.

**Shell (source-pinned only):** `export_bundle_reaper` = guard-first → `ctx.db.export_bundle().iter()` → `(chunk_id, created_at_ms)` → sort by id → seam → `chunk_id().delete(id)`.
`native_host_tests.rs:18-20` leaves `.iter()`, all writes and `identity()` **unmodelled**, so a native `#[test]` cannot execute the reducer — the split is forced, exactly as for `playtest_reaper`/`plan_reap`.

### D4 — Self-arm, arm-last (coordinator's correction; I confirm it)
`request_data_export` calls `ensure_export_bundle_reaper(ctx);` as the **last statement before `Ok(())`**, after the insert loop (`privacy.rs:1544`). Delegates to `crate::playtest::plan_reaper_arm` — already `pub(crate)` (`playtest.rs:91-107`), so **playtest.rs needs no edit**. Make `ensure_export_bundle_reaper` **private** (not `pub(crate)`): rb-22's own finding is that `pub(crate)` makes every module a legal caller.

Invariant by construction: **a chunk exists ⇒ the singleton is armed**, because the only chunk writer arms it in the same transaction, and an `Err` anywhere rolls both back.

**Trade-off to record in the ADR (my recommendation: accept + open a residual, do not wire lib.rs now):** a database holding *pre-slice legacy* chunks is swept only after the next successful export **by anyone** — the schedule is a **global** singleton, so one export by any account reaps everyone's legacy chunks. That makes the gap narrow (a DB that has legacy bundles and never receives another export). Closing it fully costs 2 lines in `lib.rs` (`init` + `sync_content`) — a disclosed hidden dependency the coordinator wants avoided. Recommend residual **R-rb-48-BOOTARM**; the arm is idempotent so it can be added later with zero risk.

### D5 — Per-tick batch cap: **include it**
`EXPORT_REAP_MAX_DELETE_PER_TICK: usize = 8192`, mirroring `playtest.rs:13`. Reducers serialize under one global write lock — privacy.rs itself cites that as the reason the export has a cooldown (`privacy.rs:1176-1178`); an uncapped delete of every expired chunk across every account is a strictly worse transaction. An interval reaper catches up on the next tick, so the cap costs nothing in correctness and buys one more pure test.

### D6 — Constants (privacy.rs, per the `EXPORT_REQUEST_COOLDOWN_MS` precedent at `:1178`; game-core is out of touches)
```
EXPORT_BUNDLE_TTL_MS: i64 = 7 * 24 * 60 * 60 * 1000;   // 604_800_000
EXPORT_REAP_INTERVAL: Duration = Duration::from_secs(300);  // 5 min
EXPORT_REAP_MAX_DELETE_PER_TICK: usize = 8192;
```
5 minutes: the TTL is a retention *ceiling*, minute precision is fine, and it matches the sibling reaper.

### D7 — No string literals, no observation
The guard's `Err` **cannot** be a string literal (`rb22p_no_bare_quote_in_privacy`, `privacy_tests.rs:806`): use `Err(stringify!(export_reaper_scheduler_only).to_string())`. Deliberately **not** `export_bundle_reaper_scheduler_only` — that token contains `export_bundle_reaper_schedule` as a prefix and would poison any bare-token census (memory: *exactly-once censuses need prefix-free ids*).
**No observation emitted** (privacy.rs bans logging by its own header contract at `:19-31`; rb-40's doctrine puts the observation in the *calling* module, and here there is no other module). Disclose as residual **R-rb-48-OBS**.

## 6. Anti-patterns to avoid, and risks

**Named anti-patterns**
1. **Loosening instead of attributing.** R1/R3/R5 all *look* like "the pin is in the way". Every one must become *exactly-N + per-body scope*, never `>= 1` or a deleted clause. (Memory: *widening a gate matcher can loosen it*.)
2. **String literal in privacy.rs.** The guard's `Err` must be `stringify!`. One quote byte reds `rb22p_no_bare_quote_in_privacy` and silently blanks later modules in a dozen concatenating evals.
3. **Prefix-colliding token.** Don't name the reject reason `export_bundle_reaper_scheduler_only` (contains the accessor as a prefix). Use `export_reaper_scheduler_only`.
4. **Contiguous `#[spacetimedb::table(` in `privacy_tests.rs`.** Raw-corpus schema parsers would see a phantom table. Fragment it, like `m22s4_nd_reducer_attr` (`:1836`).
5. **`#[cfg(test)]`-gated shipping code.** Passes count/order/tag pins while the wasm ships ungated (measured, in memory). M11 exists for this.
6. **Hand-composing the S9 transcription string.** Run the Rust test and copy the printed value (`accounts_tests.rs:13220-13225`).
7. **Editing `purge_export_bundles` (`privacy.rs:68-81`) or the `request_data_export` statements (`:1487-1544`)** — both are byte/statement frozen. The only sanctioned change is the one appended call.
8. **Adding a clause or a new eval.** ADR-0224 bans both. Every eval touch in §2 is a *roster/needle retarget on an existing clause* — say so explicitly in the ADR.
9. **Doc-comment reflow in `schema.rs:989-996`** that shifts `pub const DATA_LIFECYCLE_MANIFEST` off line 997 without updating the two `:990-992` citations.

**Risks**
- **R-A (highest): H3.** A gate currently *requires* a statement that this slice makes false. Decide up front: retarget in-slice (recommended) or park with a reviewed plan.
- **R-B:** `mkFix()` at `evals/account-e2e.eval.mjs:4496` is easy to miss; missing it turns ~15 self-tests red with a confusing `[s9/census]` message.
- **R-C:** the empirical probe's red list may surface a *seventh* privacy_tests revision (e.g. an ordering clause I judged green). Reconcile the probe output against R1-R7 before the tester starts; anything extra gets the same "attribute, don't loosen" treatment.
- **R-D:** cold-start gap (D4) — legacy chunks in a DB that never receives another export. Disclosed; residual R-rb-48-BOOTARM.
- **R-E:** `just ci` needs a live spacetime for `account-e2e`, and holds a global lock. Serialize with any sibling slice's CI.
- **R-F:** the schema baseline regen is only verifiable by `git diff` (the eval's main guard is unreliable per memory).

### 10. MEDIUM — design: an 8192-row batch of *export payloads* under the global write lock may abort every tick forever
