# Native supervisor — Monster Realm v2 (cutover 2026-07-21, Drew-directed)

**PRIMARY:** WSL-native cron loop. **FALLBACK:** the Cowork/DC scheduled task (daily 09:00, stands down while the native heartbeat is <2h old).

## Components
- `mr-native-tick.sh` (this dir) — cron entry point. Mechanical gates in pure bash (kill-switch → flock → live-chain fast-path → rate-limit reset → human-activity probe → chain-mutex TTL); spawns `claude -p` ONLY when an action may be needed. Gate log: `mr-native-tick.log` (rotates at ~1MB).
- `mr-supervisor-prompt-native.md` (this dir) — the decision run's full supervisor prompt (native-adapted; incl. resource locations + gotchas). Decision model: **sonnet** (`SUP_MODEL` env to override); rooted runs stay **opus** via `mr-launch.sh` (unchanged).
- Cron: `0 * * * *` hourly WATCHDOG + `@reboot sleep 60` (user crontab, mdrewt). Since 2026-07-24 v3 the loop is **event-driven**: finished/crashed runs, CI conclusions, and rate-limit resets fire ticks directly via `$MEM/pending-events/` + `mr-native-tick.sh <event-file>` (sources: cron|done|ci|crash|reset|manual; events REQUEUE on contention, never drop). Cron is the safety net only.
- Offload tools (all in `$MEM`; keep judgment in the LLM, mechanics in scripts): `mr-situation` (HINTS-ONLY JSON state bundle + budget governor; 45s cache; window anchored to `.weekly-reset-anchor`) · `mr-record` (validated ledger/handoff writes; wrapper-reconcile rows carry finished-run cost) · `mr-audit` (mechanical pre-merge audits; FLAGGED/AUDIT-ERROR = mandatory LLM read; hard tier always FLAGGED) · `mr-spawn` (brief+lock+detached launch+asserts from vars.json) · `mr-ci-watch` / `mr-reset-watch` (zero-token watchers that wake ticks). Bridges disable: `MR_NO_EVENT_BRIDGE=1`; escalation disable: `MR_NO_ESCALATE=1`. · `mr-ollama` (local ornith-35B via ollama, $0; coexists with the hermes agent by SHARING its model instance — tag resolution: MR_OLLAMA_MODEL env → currently-loaded ornith instance → hermes .env → `hrbrmstr/ornith-35b-fixed`; `mr-ollama model` prints the resolved tag. Engine is the raw ollama API, not the hermes CLI: faster, deterministic params, zero agent-tool surface, and no dependency on hermes gateway health): ADVISORY-ONLY event-bundle summaries (`summarize-run`, grounded on the brief scope, strict no-inference rule) + `triage` fallback when the claude CLI itself is down (auth outages). Never a gate; `MR_NO_OLLAMA=1` disables. Measured: summary ~14s, triage ~5s, ping 18s cold.
- **Model freshness policy (Drew 2026-07-24): aliases everywhere → newest of each model class automatically after CLI updates.** Keep the WSL CLI current; after each update verify with `cd $HARNESS && claude --model opus -p 'Reply OK' --output-format json` (check modelUsage keys) and watch the first tick's ledger row for the resolved ids. No version pins exist in scripts, agents (.claude/agents all use aliases), or settings.
- Model/effort routing (2026-07-24): decision ticks sonnet@medium · routine slices opus@high · HARD slices fable@xhigh (guard: 90% of the calibrated fable ALLOWANCE — own axis in mr-budget-config.json since 2026-07-25) · content opus@medium · wrapper escalates a failing opus run's final attempt to fable@xhigh (budget-guarded, identical-signature-guarded). Budget governor: SOFT-PAUSE >90% of $1,250/window (no new launches), HARD-STOP >97% (wrapper stands down pre-spawn). Governor knobs live in **`mr-budget-config.json`** (single source; bounds-validated; readers fall back to identical built-in defaults on a missing/invalid file) — recalibrate it + `.weekly-reset-anchor` at the next real park.
- WSL keepalive: `C:\Users\mdrewt\.wslconfig` (`instanceIdleTimeout=-1`, `vmIdleTimeout=-1`; effective on next WSL restart — do NOT `wsl --shutdown` while runs are live) + Startup-folder `wsl-ubuntu-boot.cmd` (boots the VM at Windows logon; schtasks needed admin, Startup folder does not).
- Health signals (epoch secs, this dir) — the fallback and `mr-supervisor-status` read these:
  - `.native-supervisor-tick-alive` — bumped at the top of EVERY tick incl. standdowns. Pure "cron is firing" liveness.
  - `.native-supervisor-heartbeat` — the fallback's stand-down gate (fresh <2h = healthy). Written at tick top ONLY while healthy; **suppressed while the most recent decision run failed and has not since succeeded**, so a logged-out / erroring loop goes stale and WAKES the fallback instead of masking the failure behind a fresh timestamp.
  - `.native-supervisor-last-success` — epoch of the last decision run that exited rc=0 (clears the failure latch, refreshes the heartbeat).
  - `.native-supervisor-last-failure` (+ `.native-supervisor-last-failure-epoch`) — set on rc!=0 with the reason (e.g. `Not logged in`); logged as `SPAWN-FAIL`. This latch is what suppresses the heartbeat until the next success.

## Controls
- **Helper commands** (`~/.local/bin`, on PATH — added 2026-07-24):
  - `mr-supervisor-status` — one-glance health: enabled/paused, schedule, **live runs (in-flight decision tick / building slices)**, heartbeat & tick-alive age, last success/failure, recent ticks, **budget/governor + fable share + pending events + watchers**. Add `-f` (raw) or `--pretty` (readable: assistant text + tool calls + brief results) to live-tail the most recent task log (the active slice build); `--log` prints its path.
  - `mr-supervisor-chat` — resume the Claude session behind any past run/tick (`list`, `<slice>`, `tick`, or `<slice> -p "question"`). Conversation memory persists; prompt cache expires after minutes-to-an-hour (a later resume re-pays ingestion but skips re-derivation). For live steering from your phone: `claude --resume <sid>` then `/remote-control` (QR → Claude app / claude.ai/code).
  - `mr-supervisor-disable` / `mr-supervisor-enable` — pause / resume the loop (toggles `.native-supervisor-disabled`; paused ticks log SKIP and exit).
  - `mr-supervisor-run` — run ONE tick now, detached; overrides the pause via `MR_FORCE=1` but still respects the concurrency / rate-limit / live-run gates.
- **Pause native loop (manual):** `mr-supervisor-disable`, or `mr-hold set --by operator --reason "..."` (ticks log SKIP and exit, reporting `queued_events=`/`oldest_event_age_h=` so a backlog stranded behind the pause is visible). Resume: `mr-supervisor-enable`. `mr-hold status` shows who holds it. A bare `touch` still works — an unattributed flag is read as OPERATOR by design (lp-09 fail-safe) — but prefer the wrappers, which record a reason. **An agent session cannot clear an operator hold**: `mr-hold clear` refuses it and `guard-bash.mjs` blocks the `rm`/`mv`/write-verb routes around it, so from a session use `MR_FORCE=1 bash mr-native-tick.sh`, which bypasses ONLY this gate for one on-demand run **without clearing the hold**. *(That guarantee was FALSE from lp-09 until 2026-08-22: the guard's anchor tolerated no path prefix, so invoking the resume wrapper by its absolute path — which `which` prints for you — went straight through. Closed in `at()`'s `PFX`; see ADR-0002's 2026-08-22 amendment. The claim is only as strong as the fixtures behind it, and there were none for the path form.)*
- **Full rollback to DC:** remove the two crontab lines (`crontab -e`), delete the heartbeat file, re-raise the Cowork task cadence via Cowork.
- **Test a tick without spending:** `MR_TICK_DRYRUN=1 bash mr-native-tick.sh` (prints DECISION-NEEDED instead of spawning).
- Decision-run transcripts: `/tmp/mr_native_tick_native-<ts>-<pid>.log`.
