# rb-108 plan — exempt a `mod` from the M22 census only when it carries `#[cfg(test)]`

Slice: rb-108 · Source: R-rb-85-MODCENSUS · Touches: server-module/src/accounts_tests.rs (+ docs/adr/266, ARCHITECTURE.md, knowledge) · ADR-0266 reserved.

## Rule
New pure fn `m22_declared_mod_names_in(src: &str) -> Vec<String>` (declaration order; no sort/dedup);
`m22_declared_mod_names()` = loop over `m22_scanned_sources()` + existing sort/dedup.
Line-oriented over a NEW single-pass, NEWLINE-PRESERVING blanker `m22_blank_for_mod_scan(src)` (REV 2, red-team
#1/#2): `//` comments, NESTED `/* */` (depth-tracked), `"…"` with escapes, `r#"…"#`, and char literals
(`'x'`, `'\n'`, `'"'`; lifetimes untouched) all become spaces, every `\n` is kept — so no blanking can merge
lines and an earlier `#[cfg(test)]` can never be glued onto a later production `mod` by a stray `"` in a
comment (the old strings-then-comments pipeline swallows across lines: MEASURED shape in test 3).
For each `mod x;` hit at line i,
walk j = i-1 downward: blank → skip; `trim().starts_with("#[")` → push `squash_ws(line)`; anything else
(incl. `#![`) → stop. Exempt iff a collected attribute == `#[cfg(test)]` exactly (squashed).
Any other cfg form (`cfg(any(test,..))`, `cfg(all(test))`, `cfg_attr`, `cfg(not(test))`) → production.
Predicate on ONE stable line: `let exempt = attrs.iter().any(|a| a == "#[cfg(test)]");` (X4 mutant anchor;
/simplify: no separate predicate helper; X4 asserts the anchor occurs exactly once before mutating — red-team #3).
Known limitation (rustfmt-impossible in this crate, do not pin): same-line `#[cfg(test)] mod x;` and
multi-attribute-per-line runs are invisible / non-exact → counted as production (fail toward coverage);
a genuinely multi-line `#[cfg(\n test\n)]` also counts as production.

## Edge classes (input → returned?)
- `#[path=..]` + `pub(crate) mod reach_privacy_tests;` (no cfg) → yes (the measured cheat)
- `#[cfg(test)] #[path] mod x_tests;` → no · 3-attr run with `#[allow]` → no
- `#[cfg(test)] #[path] mod bench_support;` (gated, no suffix) → no (old rule: yes — 2nd RED direction)
- `mod inventory;` / `pub mod x;` / `mod guards; // c` → yes
- `#[cfg(test)]` blank line(s) `mod x;` → no · `#[cfg(test)] use foo; mod bar;` → yes
- `// #[cfg(test)]` `mod x_tests;` → yes · whitespace variants of cfg(test) → no
- non-exact cfg forms, multi-line attribute → yes · commented/string mods, inline `mod x {}` → invisible
