## Survivor check

No wrong implementation above survives the WHOLE corpus in `teeth.md` — each has at least one
fixture id in the table that it fails. Two clauses (W3/W5, and to a lesser extent W1) are each
caught by more than one fixture; that overlap is deliberate redundancy (per the tester brief: "no
gating test is edited to fit a buggy implementation," so having a SECOND, independent fixture that
also catches a wrong impl means deleting or weakening any ONE fixture in response to an
implementer's confusion cannot silently let that wrong impl back in).

If, once the real implementation lands, ANY of W1-W12 is found to still pass the ENTIRE fixture
corpus (i.e. a fixture I designed to kill it turns out not to, on the REAL exported functions), that
is a fixture bug on my side to revise against this spec — never a reason to weaken the wrong-impl
definition to match what shipped.
