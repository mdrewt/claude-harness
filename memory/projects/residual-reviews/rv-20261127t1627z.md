## Evidence conventions

Each verdict was read at game `origin/master` (`git show` / `git grep`), and none comes from the row's
own text. The conventions:

- `#NNN` is the merged game PR, from its commit subject.
- `path` › "…" quotes the name, or the start of the name, of the covering test. Where marked, it
  quotes the assertion message that pins the behaviour instead.
- `path:N` or `path:N-M` gives the line or lines at `7115d0e2` that show the defect today.

The verdict classes follow these rules:

- **FIXED:** a merged PR plus a test or assertion that covers the behaviour. A row asking for dead code
  to be deleted is FIXED when the code is gone and a test pins its absence.
- **STILL-REAL:** a behaviour fixed with nothing covering it stays STILL-REAL, as the playbook says.
- **OBSOLETE:** used for two kinds of row. One is dead code deleted with nothing pinning its absence.
  The other is a comment-only or doc-only row whose stale text is gone (corrected or deleted): no test
  can pin prose, so FIXED's test condition cannot be met. The playbook does not cover that second
  case. It is recorded as a note on this slice (see below), and the supervisor may read these rows as
  `fixed` with the PR as the reason.

The supervisor's merge-tick re-check can run every citation directly.

### Cluster 1 — the tap-to-turn bound waits on the frames it judges

type: feature · tier: routine
category: netcode-determinism · severity: MED
closes: R-np-c2-tap-turn-flake
touches: client/e2e/tap-to-turn.spec.ts

The np-c2.6 case starts a frame recorder on window B and then waits for A's tile to change with a
separate `b.waitForFunction`. It stops the recorder as soon as that wait returns, and only then looks
for the first recorded off-tile frame. The error at `client/e2e/tap-to-turn.spec.ts:535` is the case
where the wait saw the change but the recorder holds no sample for it. That happened on a loaded CI
shard (master e66239ca, run 43717305033) and was green on rerun.

- **C1.1:** WHEN A's second East tap moves A off its tile, THE SYSTEM SHALL stop B's frame recorder
  only after the recorder itself holds a sample taken at or after the second tap with A off its origin
  tile. The wait polls the recorder's buffer, not a separate read of the game state, so the bound
  judges a frame the recorder actually captured.

Tests: the np-c2.6 case in `client/e2e/tap-to-turn.spec.ts`, with its existing assertions unchanged.
Two pieces of evidence: green under `npx playwright test tap-to-turn --repeat-each 20` on a host
running a CPU load, and red when the wait is put back to the separate state read and the recorder is
throttled.
