### Cluster 1 — the rules state and a wild's spawn tile are joined from rows in game-core, once

type: feature · tier: hard
category: netcode-determinism · severity: LOW
closes: R-bt-11-SHAREDJOIN
touches: game-core/src/tactics/map.rs, game-core/src/tactics/map_tests.rs, game-core/src/tactics/resolve.rs, game-core/src/tactics/resolve_tests.rs, server-module/src/tactics.rs, server-module/src/tactics_tests.rs, client-wasm/src/lib.rs, client-wasm/src/tactics_tests.rs

- **C1.1:** WHEN the server or the client builds a `TacticalState` from battle rows, THE SYSTEM SHALL
  take two things from one game-core function each: the map-derived fields (width, height, terrain,
  line-of-sight blockers) and a wild unit's spawn tile. As a result, a wild whose `wild_index` is off
  the map's `spawn_b` is refused with the same error by both, where today the server's `filter_map`
  drops it silently.

Tests: a game-core unit test of the two functions (an in-range and an off-range `wild_index`). A
client-wasm `tactics_tests.rs` case shows `state_of` and the server's join give equal states for the
same rows. A `server-module/src/tactics_tests.rs` case shows an off-map `wild_index` is refused, not
dropped.
