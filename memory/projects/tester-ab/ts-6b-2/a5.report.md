Test-world design notes for the two server tests:
- economy: shop 3 keeper X has home (20,12), radius 3 (reach 5) and its own `character` row at
  (30,20), OUTSIDE its wander disc. That is deliberate: inside the disc "within TALK_RANGE of
  the current tile but out of reach of home" cannot happen (current tile is at most r from
  home, so anything within 2 of it is within 2+r of home). With the current tile outside the
  disc, standing on it is refused and standing at home+5 (13 from the current tile) is accepted.
- Every refusal in both tests is followed, in the same fixture, by moving ONE variable (the
  tile) and getting the accepted result or the later guard's own text (battle / cooldown /
  cost item), so none can pass because an index was left empty.
- Refusals assert the literal text, a byte-identical snapshot, and zero write calls
  (`Fixture::writes_to`) on the wallet/inventory (economy) or monster/monster_pub/inventory/
  heal_cooldown (heal) tables. Wallets are not a table of the heal world (cost_currency 0), so
  a wallet write there would abort the process.
