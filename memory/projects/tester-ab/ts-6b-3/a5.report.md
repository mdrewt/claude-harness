CONTRACT LINES NOT FULLY TESTABLE / NOTES
1. heal_party "the currency cost is decided first, then the item lock/shortfall, all before any write" cannot be observed through the reducer: the currency cost comes from the process-wide cached heal locations (cost_currency 0 for every shipped location, cache not injectable). The currency half is covered through evaluate_heal_currency (heal_currency mod); the item half through heal_party with item-only costs. Whether the currency spend is moved after the item checks is not pinned by any test.
2. consume_n with qty == 0 on a MISSING stack: the contract lists "qty == 0 -> Ok, no write" and "no stack row -> Err" with no stated precedence. The test pins Ok(()) (the behaviour-preserving reading: a zero-cost loop over no stack was Ok before). If the spec intends the Err, this one assertion in consume_n_writes_the_stack_once_whatever_the_quantity must be revised from the spec.
3. talk_with_content has no quest-definitions parameter, so it must read the shipped quest definitions internally; the last sub-case of talk_refuses_a_reward_over_the_cap_before_any_write relies on that (custom tree plus npc_id "elder_oak" plus a shipped quest_001 row).
4. The host cannot show transaction rollback, so the refused-after-entry-node-grant talk case asserts only the Err, as the brief allows.
5. The write counts depend on the host counting an insert as one write and a byte-identical duplicate insert as still counted; the expected 4 in the apply_swap test assumes the credits are inserts into stacks the receivers do not hold.
