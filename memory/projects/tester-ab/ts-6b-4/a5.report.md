- The brief says the stub should answer 2 for map 13 (main.dispatch.test.ts T12). But
  BT12-2-BOOT-DEPLOY (:5596 expects three picks [P4, P1, P3] on map 13), BT12-3 (B1 and B2 on map 13,
  three picks), BT12-1-BOOT-ACTIVE-SHELL's battle C and the ts-3 trade deploys all deploy on map 13
  with three slots. A default of 2 for map 13 would cut BT12-2 to [P4, P1] and lose its "then the
  party in its order" proof (P3). So the default answer for map 13 stays 3. The tagged .2 case sets map
  13 to 2 itself (3 cells, answer 2), plus map 17 to 3 (2 cells, answer 3). The afterEach restores both.
- build_kits sets SpeciesTactics.base_speed from species.base_stats.speed
  (game-core/src/tactics/content.rs:413-417). So in live content a kit's base speed always equals its
  species' speed, and no live-content oracle (bt11_unit_join's want, the server roster test) can tell
  "base speed from the species" apart from "base speed from the kit". Only the hand-built game-core
  fixture can.
- After `just wasm` rebuilds from the frozen Rust, the built pkg's tactics_deploy_slots panics
  (todo!()). The new wasm.test case never reaches it, because the port throws a TypeError first
  (deploySlots is unbound). It also never calls the pkg export directly, so the shared wasm instance
  is not trapped.
