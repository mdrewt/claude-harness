## 1. Problem / intent

The eleventh review confirms the codebase remains architecturally disciplined: the must-never-leak RLS surface (monster genes, `battle_wild` seed, `encounter` weights, `battle_action`, `player_wallet`, `player_conversation`, `playtest_event`), the once-only rating funnel, trade debits-before-credits ordering, buy/sell reject-not-clamp, PvP action privacy/provenance, and the determinism/overflow gates all held up under direct verification. As before, residual risk clusters at the **seams between hardening waves** — an invariant proven for one reducer but not propagated to its sibling, or a generated artifact whose drift gate cannot see its own defect:

1. **The both-role ongoing-battle guard (ADR-0122) was propagated to `evolve`/`fuse` but NOT to `care`/`train`.** `care` (raising.rs:68) and `train` (raising.rs:133) carry only `require_owner` + `reject_if_monster_in_trade` — no ongoing-battle guard at all. Combined with the level-up heal branch of `write_back_battle_results`, which recomputes max-HP from the **live** monster row's EVs (`derive_stats(&base,&ivs,&evs,…)` at battle.rs:1170) and folds `new_max − snapshot_old_max` into `current_hp` (`level_up_healed_hp`, xp.rs:97), a monster can be `train`ed mid-battle to raise `ev_hp→stat_hp` and receive extra current HP on level-up that a post-battle train would not grant. ADR-0122 §D7 explicitly asserts this vector does not exist ("writes the snapshot's current_hp, never recomputed from live stat_hp; mutation testing confirmed snapshot isolation") — so this is both a real (bounded) HP-laundering path and a false claim in an accepted ADR.

2. **The wild/PvE battle row class has no disconnect resolution and no reaper.** `forfeit_on_disconnect` (pvp.rs:576,588) filters battles by `outcome == Ongoing && opponent_identity != WILD_IDENTITY`, deliberately excluding wild battles; every other ephemeral terminal-deleted table has a reaper (trade TTL, challenge TTL, pvp-deadline, playtest cap) but wild `battle` rows have none. A player who disconnects mid-wild-battle leaves an `Ongoing` `battle` row and its `battle_wild` sidecar forever, and on return `is_in_ongoing_battle` (guards.rs:254 player arm, no WILD exclusion) soft-locks them out of starting any new battle until they manually resume/flee — a persistent player-facing lockout and a slow row leak, both directly relevant to the imminent solo playtest where disconnects are common.

3. **Overlay mutual-exclusion is one-directional.** The three oldest overlay-open handlers — `KeyB`/`KeyI`/`KeyE` (main.ts:487/506/525) — gate only on battle/shop/trade/pvp/leaderboard/rename and never check `dialogueView`/`questLogView`/`healView`, while every newer handler (KeyU/KeyN/KeyO/KeyQ/…) does. Pressing B/I/E while a dialogue, quest-log, or heal overlay is open stacks a second overlay — a visible UX break a tester will hit. Root cause: overlay visibility is open-coded across ~5 sites (keydown guards, Escape ladder, movement-suppress, pvp listener, rAF loop) with 6–12 overlays each and no shared registry, so every new overlay requires ~15 lockstep edits and the B/I/E omission is exactly a missed edit.

4. **The generated OKF knowledge bundle counts test-fixture reducers, and its drift gate is blind to it.** `scripts/okf-export.mjs collectRsFiles` walks every `.rs` file with no `*_tests.rs` exclusion, so the reducer definitions inside `ranking_tests.rs`/`playtest_tests.rs` are counted (schema-overview.md claims "49 reducers"; there are 42 in non-test source) and — because the last sorted file wins — `docs/knowledge/reducers/set_profile_name.md` and `playtest_reaper.md` are generated pointing at `*_tests.rs` source lines with the wrong tags/abstract, clobbering the real reducer doc-comments. `knowledge-bundle-conformance.eval.mjs` only checks committed == regenerated, so the gate stays green while the OKF-adoption deliverable is wrong.

5. **Two gating-test teeth have degraded to vacuous passes.** Red-team test RT-M14.5A-02 (redteam_m14_5a_tests.rs:451) hits a bare `return;` before its sole assertion when its `status_applied` precondition is unmet — so a regression that stops `StatusApplied` emission turns it green while asserting nothing. And the mutate-server wiring guard (nightly-smoke-wiring.eval.mjs:318) rejects only `cap > 340` while the committed ADR-0118 baseline is 299, tolerating a silent ~41-mutant loosening.

6. **SSOT / content / dedup drift.** The `CARE_BOND_AMOUNT = 5` balance constant lives in the shell (raising.rs:38) while its consuming rule `game_core::apply_care(bond, amount)` is parameterized and pins no canonical value — unlike every sibling balance constant (game-core SSOT). `seed_heal_locations_from` (content.rs:653) is upsert-only, so a heal location removed from RON keeps its `heal_location_row` and stays usable (asymmetric with the stale-delete on zone/type/shop/fusion re-seeds). The PvP-vs-wild classifier is duplicated in `eventRing.ts:135` and `battleModel.ts:256` (drift risk). A stale comment in `connection.ts:521` claims `resetCharacters()` clears stale-zone characters on warp, but its only non-test caller does not exist.

7. **Ledger drift.** `CHANGELOG.md` stops at ADR-0127, missing the entire playtest block (ADR-0128–0133, PRs #216–#227); `PLAN.md:3` §Status still reads "Next: close M17" though M17/M17.5/pt-c are delivered.
