## 1. Why this milestone exists

Three findings, in descending order of how much they cost if left alone.

**(1) One live data exposure.** `server-module/src/schema.rs:396` is still
`#[spacetimedb::table(name = battle, public)]` and `client/src/net/connection.ts:709` subscribes
`'SELECT * FROM battle'` unfiltered inside the single 20-entry `.subscribe([…])` array at `:690-752`.

derived stats, known skills and status (`BattleMonster`, `game-core/src/combat/types.rs:41`).
ADR-0042:30 declared M16 **blocked** from reusing this schema without mitigation; M16 shipped anyway
(ADR-0109 privatised only `battle_action`). This is the same need-to-know class Drew's issue #284
decision closed for `monster_pub` (ADR-0194) — `battle` was simply never revisited.

**(2) Seven security gates are measurably blind, and the eighth-order effect is a 27,000-line scan
corpus.** `evals/scanner-migration-audit.eval.mjs:124` holds `KNOWN_UNMIGRATED_CAP = 7` with exactly
seven entries at `:137-185`, **all owned by slice id `14r-c-2`, which is defined in no spec file**
(measured: `grep -rn '14r-c-2' specs/` → 0). Two of the seven (evolution, raising) are
canary-measured to *swallow* the needle outright. `13r-c-2` — a separate, also-undefined id — owns

contain the literal `#[spacetimedb::table` — 27,243 lines, 29.1% of the 93,641-line, 87-file eval
corpus** — because schema facts that are structured data are being asserted with regexes.

**(3) There is no reducer-executing Rust test harness anywhere in the crate**, so a guard inside a
reducer is unreachable by any behavioural test — which is *why* the source-scanning exists. Measured:
18 `*_tests.rs`, 46,434 lines, 637 tests, **120 source-reading sites** (`include_str!` ×106,
`read_to_string` ×14), concentrated pvp 28/51 · evolution 15/42 · content_cache 12/28 · battle 11/51

### 15r-sec-a — Participant-scoped `battle` via a two-identity view (CRITICAL, MED-HEAVY) — game-visible
`touches: server-module/src/schema.rs, server-module/src/battle.rs, server-module/src/pvp.rs, client/src/module_bindings/ (regenerated by `just gen`, never hand-edited), client/src/net/connection.ts, client/src/net/connection.test.ts, client/src/net/store.ts, client/src/ui/battleModel.ts, client/e2e/, evals/monster-privacy.eval.mjs, evals/battle-schema-snapshot.eval.mjs`
`after:` (none) — **R13-exempt** (no dependency on gauge, kill switch or pacing band) and the only
CRITICAL live exposure. **The SpacetimeDB 2.8.1 bump is COMPLETE (2026-08-16), so this is unblocked**
— verified: CLI 2.8.1, crate 2.8.1, `schema.rs` on `accessor =`. Two consequences to act on rather
than re-derive: **view primary keys now exist**, so check whether the no-PK ingest reshape below is
still needed at all; and the attribute syntax this slice reads has *changed*, so re-measure every
`schema.rs`/scanner claim here against the bumped tree before briefing.

Make `battle` private and expose participants' own rows through a view. **W0-6 is ANSWERED** (settled
against vendored crate source, not docs — evidence in `M-loop-infrastructure.spec.md` §2.0):
`client_visibility_filter` is **inert** here and would publish clean while enforcing nothing.
`#[view]` is sound instead, because a 1.12.0 view body is **ordinary read-only Rust, not a SQL
predicate** — the two-identity OR is `.chain()` of two point-index scans, and `Battle` already carries
`#[index(btree)]` on *both* identity columns (`schema.rs:401-404`). First multi-column view in the
module, so it needs its own exact-body pin; `my_account`'s docstring records why: *"a decoy
`find(ctx.sender)` then `find(other)` compiles clean and leaks."*

**Two residuals to close, not inherit.** (1) Views return `Vec`, not a set, so `.chain()` double-emits
when a player is both sides — pinned, not hypothetical: `battle.rs:1274-1278` defines a **practice
battle** as exactly `player_identity == opponent_identity`. **Dedup explicitly; do NOT pin an
inequality invariant.** (2) **Client ingest may not be a rename.** On **1.12.0** a view binding had no
primary key, so `onUpdate` never fired and a mechanical rename broke battle rendering while `just ci`
stayed green (§6). **View PKs ship with the 2.8.1 bump this slice is now gated on**, which likely
deletes this residual — *verify it at slice head against the bumped tree rather than assuming it
either way*, and keep §6's countermeasure if `onUpdate` still does not fire.

EARS: WHEN the module is published, `battle` SHALL NOT be declared `public`. WHEN a client subscribes,
THE SYSTEM SHALL deliver only rows where that client is `player_identity` or `opponent_identity`.
WHEN a player is both participants (a practice battle), THE SYSTEM SHALL deliver that row exactly
once. WHEN a battle's state changes mid-battle, the client store SHALL reflect it and SHALL NOT drop
the row.
Tests: two-identity e2e in `client/e2e/`, **shipping with a positive control because the bare negative
is a false green** — a mis-named, ungenerated or erroring subscription also leaves B's store empty. So
assert in one spec: B sees zero rows of A's battle, **A sees its own**, and A's row survives a
turn-advance. Plus an exact-body pin in `evals/monster-privacy.eval.mjs` mirroring the
`my_monster_pub` pin. Proof-of-teeth: the e2e RED against the current `public` table; the body pin RED
against a decoy `find(other)` view (ADR-0010).
Decision-hook: **Q-B4 ANSWERED 2026-08-16 — accept the refresh.** Ship without waiting on
`15r-net-a`, which now holds a definite Wave-6 slot (§4, §7). No open decision blocks this slice.

### 15r-sec-vis — Table visibility as declared data + a class regression gate (HIGH, MED)
`touches: evals/baselines/table-schemas.json, evals/battle-schema-snapshot.eval.mjs, scripts/`
`after:` 15r-sec-a — the fix lands first; this is the gate that keeps it fixed. **No longer gated on
the SpacetimeDB bump; that is complete.** Carry one thing forward from it: 2.7.1 shifted `describe`/schema-snapshot
output (V10 retains column defaults), so confirm `battle-schema-snapshot` has already been
re-baselined before adding a `visibility` axis on top of it — do not stack a new axis on a stale
baseline.

`15r-sec-a` fixes one table. Nothing stops the next one. That is precisely how ADR-0042's constraint
was violated by M16 — the constraint existed only as prose. Measured today: `schema.rs` declares
**30 tables, 19 of them `public`**, and `evals/baselines/table-schemas.json` carries **38 entries
each with exactly `{pk, columns, order}` — the strings `public`, `private`, `visib` and `rls` appear
zero times in the whole 16,491-byte file.** Visibility is not *entirely* underived — `scripts/okf-export.mjs`
already parses it from `schema.rs` for the knowledge bundle — but nothing **gates** on it, and the
snapshot the schema gate actually reads carries no visibility axis. Reuse that parser; do not write a
second one.
**Scope honestly: this is net-new, not a re-shape.** Add a `visibility` field to each snapshot entry,
a regenerator that derives it from source (the snapshot is generated, never hand-edited), and a drift
gate on it — the same three-part shape ADR-0193's order-aware snapshot gate already uses. The payoff
is that a table flipping to `public` becomes a RED diff instead of a review that nobody runs, and
`15r-consolidate` gets something to consolidate *onto*.

EARS: WHEN the schema snapshot is regenerated, each table entry SHALL carry a `visibility` value
derived from the declaration. WHEN a table's declared visibility changes without the baseline being
re-generated in the same commit, THE SYSTEM SHALL fail the gate. WHEN a NEW table is added as
`public`, THE SYSTEM SHALL fail the gate until the baseline records that choice explicitly.
Tests: extend `evals/battle-schema-snapshot.eval.mjs`; proof-of-teeth: flip one private table to
`public` in a fixture and show the gate RED; re-baseline and show it green (ADR-0010).

### 15r-g — `.gitattributes` merge strategy for generated artefacts (MED, LIGHT)
`touches: .gitattributes`
`after:` (none) · `blocked:wave-2-exit`

Measured: `.gitattributes` is 12 lines — one comment, `* text=auto eol=lf`, nine binary patterns —
with **no `merge=` entry anywhere**; and `git config --get-regexp 'merge\.'` returns empty at **both**
local and global scope. Git's `merge=` attribute is a no-op unless a driver of that name is configured
on the machine performing the merge, so both halves are missing today. **Never `merge=union` on
human-authored prose** — union interleaves both sides with no conflict marker, producing syntactically
valid Markdown that a human discovers later. `ARCHITECTURE.md` and `docs/adr/*.md` get **no merge
attribute at all**; a conflict there is the correct outcome. `merge=ours` goes on generated artefacts
only: `docs/adr/DIGEST.md`, `docs/adr/design-corpus.json` (generated by `just adr-digest`, gated by
`adr-digest-check`) and `CHANGELOG.md` (generated by `just changelog`, never hand-edited). Mandatory
pairing: `merge=ours` discards the other side by design, so the supervisor merge recipe must
regenerate both after any merge that touched them.

**Scope note — this slice was split at review.** Its original touch-set spanned both repos
(`.gitattributes` here; `mr-selfcheck` and the supervisor prompt in the harness), which
`M-loop-infrastructure.spec.md`'s `lp-00` makes an explicit spawn-time rejection. The harness half —
driver key, its selfcheck, and the post-merge regeneration recipe — is **`lp-gitattr`** in that spec.
This half is safe to land alone precisely because `merge=ours` is **inert without the driver**, so
ordering between the halves does not matter and `15r-f` is not stranded behind another milestone.

EARS: `.gitattributes` SHALL declare `merge=ours` for exactly `docs/adr/DIGEST.md`,
`docs/adr/design-corpus.json` and `CHANGELOG.md`, and for nothing else. WHEN a merge attribute is
proposed for a human-authored file, THE SYSTEM SHALL NOT accept it.
Tests: proof-of-teeth — a **synthetic three-way merge on `DIGEST.md` resolves without conflict** once
`lp-gitattr` has configured the driver, and conflicts as before without it. (Stated this way on
purpose: "doc conflicts are now impossible" is unverifiable inside the slice; this is checkable.)

### 15r-h2 — CLI reducer-conformance harness for the irreducible residue (HIGH, HEAVY)
`touches: server-module/tests/ or scripts/ (CLI-driven), .github/workflows/nightly.yml`
`after:` 15r-h1 · `blocked:wave-3-exit`, and additionally **`blocked:lp-03`** — an `#[ignore]`d test
in an unwatched nightly job is the "gate that has never failed" anti-pattern in its purest form.

There is no Rust-side reducer-executing harness (measured; scope the word precisely — reducer
*execution* does exist via 19 Playwright specs and `evals/account-e2e.eval.mjs`, which spawns its own
in-memory server at `:1392`; what is missing is any Rust harness — `server-module` has no `tests/`
directory and its only dev-dependency is `proptest`). Adopt upstream's own shape from
`crates/testing/src/sdk.rs`: **freshly publish the module to a short-lived, initially-empty database
per test**, one `spacetime generate` pass amortised across all tests, client as a subprocess.
**Decide reuse-vs-shell-out explicitly rather than discovering it later:**
`sim-harness/src/bin/mr_load_driver.rs:2089` already implements a dependency-free raw-WebSocket
`CallReducer` client in Rust (used at `:2248`, `:2354`); its `:185` doc comment records the tradeoff
(*"spacetimedb-sdk would drag in tokio"*). Record the choice and why.

Three defences against vacuity, all required, because upstream's own pattern has the same weakness:
(1) every assertion pins the `Response text:` substring — a reducer rejection and a dead server both
surface as EXIT=1; (2) every negative assertion ships **paired with a positive control** (same
reducer, same args, an authorized identity, asserted to SUCCEED) so a typo'd reducer, wrong arity or
stale publish fails the pair rather than passing the negative; (3) reducer errors carry a stable
machine token (`E_NOT_OWNER: …`) and assertions pin the **token**, never the prose.

EARS: A Rust-side harness SHALL exist that publishes the module to a fresh, initially-empty database
per test and invokes reducers against it, with a single codegen pass shared across tests, and SHALL
run in nightly under `cargo test -- --ignored --test-threads=1`. Every assertion SHALL pin a stable
error token. Every negative assertion SHALL have a paired positive control. No assertion SHALL ship
without a demonstrated RED against its injected defect. The reuse-vs-shell-out choice SHALL be
recorded with its reason.
Tests: the suite is `#[ignore]`-gated and runs `cargo test -- --ignored --test-threads=1` in nightly
(the workspace currently has **zero** `#[ignore]` attributes — this establishes the convention).
Operational note: `spacetime --version` now prints a two-line upgrade banner before the version, so
any CLI probe must tolerate it.

### 15r-tst-i — Mutation ratchet on survival RATE, not absolute cap (MED, MED)
